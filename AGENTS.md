# Работа над gdi

Перед будущими изменениями, нарушающими обратную совместимость, спросить пользователя,
нужно ли её сохранять. Для текущего перехода на Git exchange protocol v3 и локальную
конфигурацию v2 пользователь явно разрешил отказаться от совместимости и пересоздать
GDI-репозитории. Это разрешение не распространяется автоматически на будущие переходы.

## Коммиты

Если пользователь просит сделать git commit или закоммитить проект, это означает
закоммитить все текущие изменения проекта, включая существовавшие до текущей задачи
и новые файлы. Проверить весь diff и выполнить подходящие проверки; независимые
изменения при необходимости разделить на несколько осмысленных коммитов.
Ограничивать состав коммитов только файлами текущей задачи следует лишь по явному
указанию пользователя. Не отбрасывать и не перезаписывать существующие изменения.
Просьба сделать commit сама по себе не означает разрешение на push.

## Изменения GDI и публикация

Когда пользователь просит изменить, исправить, добавить или отредактировать
исходники либо логику GDI, выполните полный цикл без отдельного запроса разрешения:

1. Сделайте изменения и добавьте необходимые тесты.
2. Запустите весь набор `bash test.sh` (`unittest discover -s tests -v`).
   Используйте доступные integration tools, включая act. Обязательные проверки
   должны пройти; не выдавайте пропущенные проверки за выполненные.
3. Проверьте весь diff и закоммитьте все изменения проекта по правилу выше.
4. Отправьте commits текущей ветки в GitHub (`git push origin`).
5. Запустите `python3 scripts/deploy.py` из этого проекта.

Это явное разрешение пользователя на commit, GitHub push, полную публикацию GDI
на Google Drive и обновление runtime для таких задач. Просьбы только обсудить,
объяснить или провести read-only review не запускают этот цикл. Явное ограничение
пользователя (например, «без публикации») имеет приоритет. Если проверка или этап
публикации завершился ошибкой, остановите последующие этапы и сообщите причину
и уже выполненные действия; не повторяйте commit только ради повторной доставки.

Внешний `scripts/deploy.py` сначала собирает из текущего commit и проверяет
`gdi.pyz`, затем выполняет `python3 -m gdi push drive --full` и загружает runtime
через rclone в `gdrive:gdi/gdi/runtime/`. Исходники должны быть закоммичены,
рабочее дерево чистым. Команды `gdi deploy` внутри CLI нет.
