## Контракт

- Отдельная offline-команда `gdi agent snapshot-build --capture CAPTURE
  --repository-id ID --output SNAPSHOT` создаёт существующий snapshot v1.
- Версионированный адаптер читает сохранённые ответы коннектора, автоматически
  переносит имена, IDs и размеры, связывает downloads с listing и проверяет
  результат существующим `Snapshot`. Независимо доверенный Repository ID обязателен.
- Неизвестные/несовместимые форматы, ошибки коннектора, неполный listing и
  несовпадающие downloads дают ненулевой exit и `SNAPSHOT_BUILD_ERROR` с причиной.
  Агент сообщает отказ оператору; ручной обход сборщика запрещён.
- Входы сохраняются. Выход создаётся атомарно и не перезаписывает существующий
  snapshot. Capture, ответы и скачанные файлы остаются рядом; output — в том же
  каталоге, чтобы `local_path` snapshot v1 не менял смысл.
- Текущий адаптер `google-drive-list-folder-v1` основан на проверенных именах полей
  `list_folder` и raw `fetch`. Поддерживает полные одиночные listings с явным
  `top_k` 1…100, при достижении лимита или признаке пагинации отказывает.
  Свежесть/полнота реального Drive остаётся обязанностью коннектора.
- Отчёт различает проверенные manifests, необходимые/присутствующие bundles,
  проверку содержимого bundles и независимо подтверждённую свежесть Drive.
- `agent snapshot` сохраняет прежние поля, добавляя секцию `validation`.
  Операторские команды, transport, данные Drive и версии протоколов не меняются.
